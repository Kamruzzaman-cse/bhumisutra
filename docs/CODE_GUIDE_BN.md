# ভূমিসূত্র: কোড বোঝার গাইড (বাংলা)

রুলবুক অনুযায়ী জাজরা জিজ্ঞেস করতে পারেন যে কোড তোমরা নিজেরা ব্যাখ্যা করতে পারো কিনা। এই গাইডটা পড়ে প্রতিটি অংশ নিজের ভাষায় বলার অভ্যাস করো। দুজনেরই পড়ে রাখা দরকার।

---

## ১. পুরো সিস্টেম এক লাইনে

প্রতিটি লেনদেন (দলিল, নামজারি, বন্ধক) একটা **ব্লক** হিসেবে লেজারে যোগ হয়। প্রতিটি ব্লকের একটা **হ্যাশ** (ডিজিটাল ফিঙ্গারপ্রিন্ট) থাকে, আর সেই ব্লক **আগের ব্লকের হ্যাশও** নিজের ভেতরে রাখে। এজন্য পুরোনো কোনো ব্লক বদলালে শিকল ভেঙে যায়।

## ২. ফাইলগুলো কোনটা কী করে

| ফাইল | কাজ |
|---|---|
| `crypto.js` | ডেটাকে নির্দিষ্ট ক্রমে সাজায় (canonical JSON), তারপর SHA-256 হ্যাশ বানায় |
| `data.js` | কাল্পনিক ডেমো ডেটা: দাগ, খতিয়ান, ব্যক্তি, মামলা, খাস, অধিগ্রহণ |
| `ledger.js` | লেজার বানানো, নতুন ব্লক যোগ, পুরো শিকল যাচাই (`verify`), টেম্পার ল্যাব |
| `engine.js` | নিয়মকানুন: মালিক কে, দ্বৈত বিক্রি, দ্বৈত বন্ধক, খতিয়ানের অমিল, ঝুঁকি স্কোর |
| `i18n.js` | সব লেখা বাংলা ও ইংরেজিতে |
| `ui.js` | বাংলা সংখ্যা, টাকা (৳), তারিখ, QR কোড বানানো |
| `views.js` | প্রতিটি স্ক্রিন (পেজ) |
| `app.js` | অ্যাপ চালু করা, URL অনুযায়ী পেজ দেখানো (`#/check`, `#/verify` …) |

## ৩. হ্যাশ কীভাবে কাজ করে (`crypto.js`)

```js
function canonical(value) { ... keys sorted ... }
async function sha256(text) { crypto.subtle.digest('SHA-256', ...) }
```

- **কেন canonical?** একই তথ্য `{a:1, b:2}` আর `{b:2, a:1}` দুইভাবে লেখা যায়। key সাজিয়ে নিলে একই তথ্য থেকে সবসময় একই লেখা তৈরি হয়, তাই একই হ্যাশ আসে।
- **SHA-256** যেকোনো দৈর্ঘ্যের লেখা থেকে ৬৪ অক্ষরের একটা হ্যাশ বানায়। একটা অক্ষর বদলালেই পুরো হ্যাশ বদলে যায়, যাকে বলে avalanche effect। হ্যাশ থেকে আসল তথ্য ফেরত বের করা যায় না।
- আমরা ব্রাউজারের নিজস্ব **Web Crypto API** ব্যবহার করেছি, কোনো বাইরের লাইব্রেরি লাগেনি।

## ৪. লেজার (`ledger.js`)

প্রতিটি ব্লকের গঠন:

```js
{ index, timestamp, type, payload, prevHash, hash }
hash = SHA-256( canonical({ index, timestamp, type, payload, prevHash }) )
```

- `makeBlock()`: আগের ব্লকের hash নিয়ে `prevHash` বসায়, তারপর নিজের hash হিসাব করে।
- `verify()`: প্রতিটি ব্লকের জন্য দুটো জিনিস দেখে:
  1. **hashOk**: সংরক্ষিত hash আর নতুন করে হিসাব করা hash এক কিনা (তথ্য বদলানো হয়েছে কিনা)।
  2. **linkOk**: `prevHash` আসলেই আগের ব্লকের hash কিনা (শিকল ঠিক আছে কিনা)।
- `tamper()`: টেম্পার ল্যাবের জন্য। **naive** আক্রমণকারী শুধু তথ্য বদলায়, তাই সেই ব্লকেই ধরা পড়ে। **smart** আক্রমণকারী hash-ও নতুন করে বানায়, তাই পরের ব্লকের link ভেঙে যায়।
- **Genesis block** হলো প্রথম ব্লক, এর `prevHash` ৬৪টা শূন্য।
- **ব্লক #১ (KHATIAN_BATCH_ANCHORED)** সব ডিজিটাইজড খতিয়ানের হ্যাশ ধরে রাখে, তাই খতিয়ান বদলালেও ধরা পড়বে।
- ডেমো ডেটার timestamp নির্দিষ্ট করে দেওয়া, তাই সব কম্পিউটারে একই hash তৈরি হয়। এজন্যই এক কম্পিউটারে প্রিন্ট করা QR অন্য ফোনে স্ক্যান করলেও যাচাই হয়।
- ডেটা `localStorage`-এ সেভ থাকে, তাই রিলোড করলেও হারায় না।

## ৫. নিয়ম (`engine.js`)

### `derive(chain)`: মালিক কে?
লেজারের শুরু থেকে প্রতিটি ব্লক একে একে "replay" করে:
- `DEED_REGISTERED` পেলে **deedOwners**-এ বিক্রেতার কাছ থেকে জমি কমায়, ক্রেতার নামে যোগ করে।
- `MUTATION_APPROVED` পেলে একই কাজ **recordOwners**-এ করে।
- দুটো আলাদা হলে বোঝা যায় "রেজিস্ট্রি হয়েছে, নামজারি হয়নি"। এটা P3-এর তৃতীয় অংশ।

### `checkSale()`: রেজিস্ট্রির আগে যাচাই
- বিক্রেতার কাছে যথেষ্ট জমি আছে কিনা দেখে। না থাকলে আর সে আগে এই দাগ বিক্রি করে থাকলে → **দ্বৈত বিক্রি**, আগের দলিল নম্বর দেখায়।
- খাস, অধিগ্রহণ, মামলা বা বন্ধক থাকলে → `fail`।
- খতিয়ানে অমিল থাকলে বা নামজারি বাকি থাকলে → `warn` (রেজিস্ট্রি করা যায়, তবে সতর্কতা দেখায়)।
- যেকোনো একটা `fail` থাকলেই রেজিস্ট্রি আটকে যায়।

### `checkMortgage()`
একই দাগে আগে থেকে সক্রিয় বন্ধক থাকলে → **দ্বৈত বন্ধক** আটকে দেয়।

### `assess()`: নিরাপত্তা স্কোর
১০০ থেকে শুরু হয়, প্রতিটি ঝুঁকির জন্য নম্বর কাটা যায়:

| ঝুঁকি | কাটা যায় |
|---|---|
| লেজারে কারচুপি | ১০০ |
| খাস জমি | ১০০ |
| অধিগ্রহণ | ৬০ |
| চলমান মামলা | ৪৫ |
| বন্ধক | ৩০ |
| নামজারি হয়নি | ২৫ |
| খতিয়ানে অমিল | প্রতিটির জন্য ১০, সর্বোচ্চ ২৫ |
| আগে জালিয়াতির চেষ্টা হয়েছে | ১০ |

৮০ বা তার বেশি হলে সবুজ (নিরাপদ), ৫০–৭৯ হলে হলুদ (সাবধান), ৫০-এর নিচে লাল (কিনবেন না)।

### `khatianIssues()`
পাশাপাশি দুটো জরিপে (CS→SA, SA→RS, RS→BS) মালিকের নাম বদলেছে কিন্তু কোনো কারণ লেখা নেই (যেমন উত্তরাধিকার), অথবা জমির পরিমাণ বদলেছে, তাহলে সেটাকে অমিল হিসেবে দেখায়।

## ৬. দলিল যাচাই (`views.js` → verify)
- **নম্বর দিয়ে:** লেজারে দলিলটি খোঁজে। না পেলে "জাল"। পেলে ব্লকটি অক্ষত কিনা দেখে, তারপর লেজারের আসল তথ্য দেখায়।
- **QR দিয়ে:** QR-এ থাকে `#/verify?deed=D-2019-0451&h=<hash-এর প্রথম ১২ অক্ষর>`। hash না মিললে "QR মেলেনি" দেখায়।
- **ফাইল দিয়ে:** ফাইলের দলিল আর লেজারের দলিল field ধরে ধরে তুলনা করে (`diffDeed`), আর দুটো ফিঙ্গারপ্রিন্ট পাশাপাশি দেখায়।

## ৭. রেজিস্ট্রি → নামজারি সংযোগ (P4-এর ছোঁয়া)
দলিল রেজিস্ট্রি হলে কোড নিজে থেকেই `mutationQueue`-তে একটা আবেদন যোগ করে। এসি ল্যান্ড অনুমোদন দিলে `MUTATION_APPROVED` ব্লক তৈরি হয়।

## জাজদের সম্ভাব্য প্রশ্ন ও উত্তর

**প্রশ্ন: এটা কি blockchain?**
উত্তর: এটা blockchain-এর মূল ধারণা, অর্থাৎ hash-chain, যা দিয়ে কারচুপি ধরা যায়। কিন্তু cryptocurrency বা mining নেই, তাই দ্রুত ও কম খরচের। সরকারি ব্যবহারের জন্য permissioned ledger উপযুক্ত, যেখানে কপি থাকবে সাব-রেজিস্ট্রি, এসি ল্যান্ড, DLRS ও ডিসি অফিসে।

**প্রশ্ন: কেউ পুরো লেজারের সব hash নতুন করে বানিয়ে ফেললে?**
উত্তর: এক জায়গায় থাকলে সেটা সম্ভব। তাই আসল ব্যবস্থায় লেজারের কপি একাধিক অফিসে থাকবে, আর সর্বশেষ hash নিয়মিত প্রকাশ করা হবে। একটা কপি বদলালে বাকিগুলোর সাথে মিলবে না। প্রতিটি ব্লকে কর্মকর্তার ডিজিটাল সিগনেচারও যোগ হবে।

**প্রশ্ন: ডেটা কোথা থেকে নিয়েছেন?**
উত্তর: সব নিজেদের বানানো কাল্পনিক ডেটা, `data.js`-এ আছে। কোনো আসল নাম, NID বা সরকারি ওয়েবসাইটের ডেটা নেই।

**প্রশ্ন: AI কোথায় ব্যবহার করেছেন?**
উত্তর: Claude দিয়ে কোড লেখা ও ডিজাইনে সাহায্য নিয়েছি, যা README-তে লেখা আছে। প্রতিটি অংশ আমরা পরীক্ষা করেছি এবং ব্যাখ্যা করতে পারি।

**প্রশ্ন: সারাদেশে কীভাবে চালু হবে?**
উত্তর: প্রথমে এক উপজেলায় পাইলট। তারপর বিদ্যমান ই-নামজারি, আদালত, ব্যাংক সিস্টেমের সাথে অনুমোদিত API সংযোগ, আর ধাপে ধাপে বাকি উপজেলায় বিস্তার।

**প্রশ্ন: পুরোনো কাগজের দলিল কী হবে?**
উত্তর: পুরোনো রেকর্ড ডিজিটাইজ করার সময় প্রতিটির hash লেজারে anchor করা হয় (ব্লক #১-এর মতো)। এরপর থেকে সেগুলোর কোনো পরিবর্তন ধরা যায়। ভবিষ্যতে OCR দিয়ে স্ক্যান থেকে তথ্য বের করা যাবে।

**প্রশ্ন: ইন্টারনেট না থাকলে?**
উত্তর: প্রোটোটাইপের সব কোড ব্রাউজারে চলে, এমনকি QR লাইব্রেরিও প্রজেক্টের ভেতরে রাখা। আসল ব্যবস্থায় অফিস অফলাইনে কাজ করে পরে sync করতে পারবে।

# v2: নতুন অংশগুলো

## ৮. লগইন ও অ্যাক্সেস নীতি (`auth.js`)
- `USERS`: কর্মকর্তাদের ৫টা ডেমো অ্যাকাউন্ট (subreg, acland, survey, bank, admin), সবগুলোর পাসওয়ার্ড `demo1234`। নাগরিকেরা NID, জন্মতারিখ আর OTP দিয়ে ঢোকেন (নিচে ১২ নম্বর অংশ দেখুন)।
- `SCREENS`: কোন পাতা কোন ভূমিকা খুলতে পারবে। তালিকায় না থাকলে পাতাটা সবার জন্য খোলা।
- `POLICY`: কোন তথ্য কে দেখবে। মানগুলো হলো `full` (দেখতে পারবে), `own` (শুধু নিজের জমির), `masked` (আছে কিনা জানবে, বিস্তারিত না) আর `none`।
- `see(item, ownerIds)`: স্ক্রিনে কিছু দেখানোর আগে এই ফাংশন জিজ্ঞেস করা হয়। উত্তর `false` হলে "অনুমতি ছাড়া দেখা যাবে না" দেখায়।
- `audit()`: প্রতিটি সরকারি কাজ (লগইন, রেজিস্ট্রি, অনুমোদন, ডিজিটাইজ ইত্যাদি) অডিট লগে যায়।
- ৩০ মিনিট কিছু না করলে নিজে থেকে লগআউট হয়ে যায়।
- **জাজ প্রশ্ন করতে পারেন: "পাসওয়ার্ড ব্রাউজারে কেন?"** উত্তর: এটা শুধু ডেমোর জন্য, যাতে জাজরা সহজে ঢুকতে পারেন (মেন্টরও তাই বলেছিলেন)। আসল ব্যবস্থায় কর্মকর্তারা সরকারি SSO দিয়ে আর নাগরিকেরা NID ও OTP দিয়ে লগইন করবেন, আর পুরো যাচাইটা সার্ভারে হবে।

## ৯. নথি ডিজিটাইজেশন / OCR (`ocr.js`, `views2.js`)
1. **Tesseract.js** একটা ওপেন-সোর্স OCR ইঞ্জিন, যা WebAssembly দিয়ে ব্রাউজারের ভেতরেই চলে। বাংলা (`ben`) আর ইংরেজি (`eng`) ভাষার ডেটা প্রজেক্টের ভেতরে রাখা, তাই ইন্টারনেট লাগে না আর ছবিও কোথাও পাঠানো হয় না।
2. `tessedit_pageseg_mode = 4` সেট করা আছে। এতে টেবিলের প্রতিটি সারি এক লাইন হিসেবে পড়া হয়, যা খতিয়ানের ছক পড়ার জন্য সবচেয়ে ভালো কাজ করে।
3. `parse()` প্রথমে বাংলা সংখ্যাকে ইংরেজি সংখ্যায় বদলায় (যেমন ৩১২ থেকে 312)। তারপর লেবেল ধরে regex দিয়ে মান বের করে, যেমন `মৌজা:`, `জে.এল. নং`, `খতিয়ান নং`, `দাগ নং`। যে লাইনে "পিতা" বা "স্বামী" আছে সেটাকে মালিকের লাইন ধরা হয়। যে লাইনে সংখ্যা, জমির শ্রেণী (নাল/ভিটা…) আর দশমিক সংখ্যা আছে সেটাকে দাগের সারি ধরা হয়।
4. প্রতিটি ঘরের পাশে OCR-এর **নিশ্চয়তা (%)** দেখায়। ৮৫%-এর বেশি হলে সবুজ, ৭০ থেকে ৮৫% হলে হলুদ, তার কম হলে লাল।
5. `validate()` হিসাব মিলিয়ে দেখে: মালিকদের অংশের যোগফল ১.০০০ কিনা, সব দাগের জমির যোগফল "মোট জমি"-র সমান কিনা, আর মোট জমি × অংশ = অংশানুযায়ী জমি হচ্ছে কিনা।
6. **দলিল বনাম খতিয়ান মিলানো (cross-check):** দলিলের দাতা খতিয়ানে মালিক কিনা, দাগটা ওই খতিয়ানে আছে কিনা, আর দাতার অংশে যতটুকু জমি আছে তার চেয়ে বেশি বিক্রি হচ্ছে কিনা।
7. সংরক্ষণ করলে রেকর্ডের SHA-256 আর **মূল স্ক্যান ফাইলের SHA-256** দুটোই `DIGITIZED_RECORD` ব্লকে লেজারে যায়।
- **জাজ প্রশ্ন করতে পারেন: "হাতের লেখা পুরোপুরি পড়তে পারে?"** উত্তর: না, পুরোপুরি পারে না, আর আমরা সেটা লুকাইনি। তাই "human-in-the-loop" রাখা হয়েছে: কম নিশ্চয়তার ঘর লাল দেখায় আর কর্মকর্তা ঠিক করে দেন। কর্মকর্তারা যত রেকর্ড ঠিক করবেন, সেগুলো দিয়েই ভবিষ্যতে বাংলা হাতের লেখার একটা মডেল প্রশিক্ষণ দেওয়া যাবে।

## ১০. ভূমি উন্নয়ন কর (`engine.js`)
- `currentFY()`: অর্থবছর শুরু হয় ১ জুলাই, তাই অক্টোবর ২০২৬ মানে ২০২৬–২৭ অর্থবছর।
- `holdingStatus()`: হোল্ডিংয়ের অবস্থা বের করে, অর্থাৎ মওকুফ, হালনাগাদ, নাকি কত বছরের কত টাকা বকেয়া। লেজারে থাকা `LD_TAX_PAID` ব্লকগুলোও হিসাবে ধরা হয়।
- রেজিস্ট্রির আগে বিক্রেতার কর বকেয়া থাকলে `taxDue` চেক `fail` হয়।
- কৃষি জমি ২৫ বিঘা পর্যন্ত মওকুফ দেখানো হয়েছে।

## ১১. খোঁজা ও "কোথা থেকে কোথায়"
- মৌজা বেছে দাগ বা খতিয়ান নম্বর দিয়ে খোঁজা যায়।
- শাপলাপুর মৌজার পুরো ডেটা আছে। কাশফুল মৌজা শুরুতে খালি থাকে, ডিজিটাইজ করার পর সেখানে রেকর্ড আসে।
- `plotFlow()` দুটো ধাপে ইতিহাস সাজায়: আগে জরিপের রেকর্ড (CS → SA → RS → BS, সাথে উত্তরাধিকার বা "কারণ নেই"), তারপর দলিলগুলো (দাতা → গ্রহীতা, নামজারি হয়েছে কিনা)।


# v3: ভূমিসূত্র সুরক্ষা (P3 মূল, P6 আমাদের উদ্ভাবন)

**বিচারকদের এক লাইনে বলার মতো কথা:** "আমাদের মূল সমস্যা P3। জমি বিক্রির আগেই জালিয়াতি আটকাই। P1, P2, P4, P5 এর সাথে যুক্ত। আর P6 হলো আমাদের নিজস্ব উদ্ভাবন: মালিকের সম্মতি, ৭২ ঘণ্টার নোটিশ, এসক্রো, জমি লক আর ওয়ারিশ সুরক্ষা।"

## ১২. নাগরিক লগইন: NID + জন্মতারিখ + OTP (`auth.js`, `views3.js`)
- `findCitizen(nid, dob)` প্রথমে `engine.personByNid()` দিয়ে NID খোঁজে (বাংলা সংখ্যা দিলেও চলে)। তারপর জন্মতারিখ মেলায়। মৃত ব্যক্তির NID দিয়ে লগইন করা যায় না।
- মিললে `startChallenge()` একটা চ্যালেঞ্জ তৈরি করে: ব্যক্তির পছন্দের মাধ্যম (SMS বা ইমেইল) অনুযায়ী একটা র‍্যান্ডম ৬ সংখ্যার কোড বানানো হয় (`sec.otp()`, যা `crypto.getRandomValues` দিয়ে তৈরি)।
- ডেমোতে কোডটা স্ক্রিনের একটা "ফোন" বক্সে দেখায় (`mountDevice`)। আসল ব্যবস্থায় SMS গেটওয়ে বা ইমেইলে যাবে।
- লগইনের পর ওপরে NID দেখায় এভাবে: `•••••• 1006`।
- ডেমো NID সব কাল্পনিক: ১০ সংখ্যা, শুরু `000` দিয়ে। কোনো আসল মানুষের NID বা NID কার্ডের ডিজাইন ব্যবহার করা হয়নি।

## ১৩. প্রবাসীদের জন্য সম্মতি: SMS ও ইমেইল (`views3.js`, `data.js`)
- সমস্যা: প্রবাসীদের বাংলাদেশি সিম বিদেশে চলে না, তাই দেশি SMS গেটওয়ে সবসময় কাজ করে না।
- সমাধান: মালিক নিজের পছন্দমতো **SMS** অথবা **ইমেইল** বেছে নিতে পারেন (`data.js`-এ প্রতিটি ব্যক্তির `consent` ফিল্ড)। ইমেইল যেকোনো দেশ থেকেই পৌঁছায়, তাই বিদেশে থাকা মালিকদের জন্য (যেমন সেলিনা আক্তার, ইতালি) ইমেইল সুপারিশ করা হয়।
- দুটো চ্যানেলই একইভাবে কাজ করে: `startChallenge()` একটা ৬ সংখ্যার র‍্যান্ডম কোড বানায় (`sec.otp()`), আর ডেমোতে সেটা স্ক্রিনে "ফোন" বা "ইমেইল" বক্সে দেখানো হয় (`mountDevice`)। আসল ব্যবস্থায় SMS গেটওয়ে বা ইমেইল সার্ভিসের মাধ্যমে পাঠানো হবে।
- আগে একটা Authenticator-অ্যাপ (RFC 6238 TOTP) বিকল্প আর একজন মনোনীত ব্যক্তি (nominee) বিকল্পও ছিল। সেগুলো বাড়তি জটিলতা তৈরি করছিল, তাই বাদ দিয়ে শুধু SMS আর ইমেইল রাখা হয়েছে — দুটোই সহজ আর প্রবাসীদের জন্যও যথেষ্ট।

## ১৪. অফিসের ডিজিটাল স্বাক্ষর ও QR (`security.js` → `sign`, `verify`, `signedLink`)
- আগের QR শুধু একটা লিংক ছিল। যে ফোনে লেজার নেই, সেখানে সেটা কিছু প্রমাণ করতে পারত না।
- এখন QR-এর ভেতরেই দলিলের মূল তথ্য (JSON → base64url) আর অফিসের **ECDSA P-256 স্বাক্ষর** থাকে: `#/scan?k=deed&d=...&s=...`।
- স্ক্যান করলে `V.scan` অফিসের **public key** দিয়ে স্বাক্ষর মিলিয়ে দেখে। একটা অক্ষরও বদলালে স্বাক্ষর মেলে না, আর "জাল বা পরিবর্তিত QR" দেখায়।
- একই কাজ হয় করের রসিদ আর জমির সাইনবোর্ডের QR-এও।
- **জাজ প্রশ্ন: "private key তো ব্রাউজারে, তাহলে যে কেউ সই করতে পারবে?"** উত্তর: হ্যাঁ, ডেমোতে পারবে। এটা আমরা README-তে খোলাখুলি লিখেছি। আসল ব্যবস্থায় private key থাকবে অফিসের HSM (hardware security module)-এ, জাতীয় PKI (CCA)-এর অধীনে। ফোনে যাবে শুধু public key, যা দিয়ে যাচাই করা যায় কিন্তু সই করা যায় না।

## ১৫. NID গোপনীয়তা
- `maskNid()` NID-এর শুধু শেষ ৪ সংখ্যা দেখায়।
- যাদের অনুমতি আছে (সাব-রেজিস্ট্রার, এসি ল্যান্ড, ব্যাংক), তারা "দেখুন" চাপলে পুরো নম্বর দেখতে পান। প্রতিবার দেখা অডিট লগে ওঠে (`act.nid.reveal`)।
- লেজারে NID নিজে রাখা হয় না, রাখা হয় `SHA-256(salt + NID)`। এতে প্রমাণ করা যায় "একই মানুষ", কিন্তু নম্বরটা কেউ ফেরত বের করতে পারে না।
- কেন এত সতর্কতা: ২০২৩ আর ২০২৫ সালে নির্বাচন কমিশনের NID তথ্য ফাঁসের খবর এসেছে। তাই আমরা যত কম সম্ভব NID দেখাই।

## ১৬. নিরাপদ রেজিস্ট্রির ধাপ (`views3.js` → `V.register`)
1. **যাচাই:**
   - `checkSale()` চালানো হয়।
   - পুরোনো চেকগুলো তো আছেই, নতুন যোগ হয়েছে:
     - `fakeNid`: NID সার্ভারে নেই
     - `deceased`: বিক্রেতা মৃত
     - `heirShare`: ওয়ারিশ নিজের অংশের বেশি বেচছেন
     - `locked`: জমি লক করা
     - `pendingNotice`: আগে থেকেই একটা বিক্রি নোটিশে আছে
     - `watchlist`: এই জমিতে আগে জালিয়াতির চেষ্টা হয়েছে
   - কোনো চেক `fail` হলে ওখানেই থামে, আর এই চেষ্টাটা ওয়াচলিস্ট ও মালিকের সতর্কবার্তায় যায়।
2. **মালিকের সম্মতি:** মালিকের পছন্দের মাধ্যমে কোড যায়। সঠিক কোড ছাড়া সামনে যাওয়া যায় না।
3. **নোটিশ:** `NOTICE_PUBLISHED` ব্লক লেজারে যায়, আর বিক্রিটা প্রকাশ্য নোটিশ বোর্ডে ওঠে ৭২ ঘণ্টার জন্য। যে কেউ আপত্তি দিতে পারেন। আপত্তি থাকলে কর্মকর্তা আগে সেটা খারিজ বা গ্রহণ করবেন। ডেমোতে "৭২ ঘণ্টা বাদ দিন" বোতাম আছে।
4. **চূড়ান্ত:** তিনটা জিনিস একসাথে হয়: `DEED_REGISTERED`, `ESCROW_HELD` (টাকা আটকে থাকে), আর নামজারির আবেদন।
5. এসি ল্যান্ড নামজারি অনুমোদন করলে `ESCROW_RELEASED` হয়, তখন টাকা বিক্রেতার কাছে যায়।
- **কেন এসক্রো:** জাল বিক্রি ধরা পড়লে টাকা তখনও আটকে থাকে, ক্রেতা টাকা হারান না।

## ১৭. জমি লক (`LAND_LOCK`)
- মালিক "আমার জমি" পাতা থেকে লক চালু করেন। পরিবর্তনটা নিশ্চিত করতে নিজের কোড দিতে হয়।
- লক থাকলে `checkSale` আর `checkMortgage` দুটোই `fail` হয়।
- প্রতিটি লক বা আনলক লেজারে ব্লক হিসেবে থাকে, তাই পরে কেউ বলতে পারবে না "লক ছিল না"।

## ১৮. উত্তরাধিকার ও ফারায়েজ (`engine.faraiz`, `SUCCESSION_RECORDED`)
- ডেমো ঘটনা: রফিক (P07) ২০২৪ সালে মারা গেছেন। দাগ ৩১৭-তে তাঁর ৫০ শতাংশ জমি ছিল। ওয়ারিশ সনদ WS-2024-0042 অনুযায়ী জমি ভাগ হয়েছে এভাবে:

  | ওয়ারিশ | সম্পর্ক | পেয়েছেন |
  |---|---|---|
  | আমেনা | স্ত্রী | ১/৮ = ৬.২৫ শতাংশ |
  | রাসেল | ছেলে | ১৭.৫ শতাংশ |
  | সোহেল | ছেলে | ১৭.৫ শতাংশ |
  | রুমানা | মেয়ে | ৮.৭৫ শতাংশ |

  ছেলে আর মেয়ের ভাগ ২:১ অনুপাতে।
- `derive()` এই ব্লক পেলে মৃত ব্যক্তির জমি দুই মালিকানা হিসাবেই (দলিল আর রেকর্ড) ওয়ারিশদের নামে সরিয়ে দেয়।
- তাই রাসেল পুরো ৫০ শতাংশ বেচতে চাইলে `heirShare` চেক আটকে দেয়। তিনি বেচতে পারবেন শুধু নিজের ১৭.৫।
- `faraiz()` ক্যালকুলেটর যা যা মানে:
  - নির্দিষ্ট অংশ:
    - স্বামী: ১/২ বা ১/৪
    - স্ত্রী: ১/৪ বা ১/৮
    - মা: ১/৩ বা ১/৬
    - বাবা: ১/৬
    - মেয়ে: ১/২ বা ২/৩
  - বাকি অংশ ছেলে-মেয়ের মধ্যে ২:১ হারে।
  - যোগফল ১-এর বেশি হলে **আউল**: সবার অংশ আনুপাতিক হারে কমে।
  - কিছু বাকি থাকলে **রদ্দ**: স্বামী বা স্ত্রী ছাড়া অন্যদের মধ্যে আবার ভাগ হয়।
  - "উমারিয়াতাইন" নিয়ম।
- সীমা: ভাই-বোন আর নাতি-নাতনির হিসাব এখনো নেই। স্ক্রিনে বলা আছে, "চূড়ান্ত বণ্টনের জন্য আদালতের ওয়ারিশ সনদ লাগবে।"

## ১৯. জমির QR সাইনবোর্ড আর নোটিশ বোর্ড
- `V.sign`: জমির সীমানা খুঁটিতে লাগানোর মতো একটা ছাপার উপযোগী বোর্ড। ক্রেতা জমিতে দাঁড়িয়েই QR স্ক্যান করে আসল রেকর্ড দেখতে পান, দালালের কথায় নির্ভর করতে হয় না।
- `V.notices`: সব চলমান বিক্রির তালিকা। লগইন ছাড়াও দেখা যায় আর আপত্তি দেওয়া যায়।

## v3-এর জন্য জাজদের সম্ভাব্য প্রশ্ন
- **"বাস্তবে NID কীভাবে যাচাই করবেন?"** নির্বাচন কমিশনের NID verification service-এর অনুমোদিত partner API দিয়ে। বর্তমানে ব্যাংক আর মোবাইল অপারেটররাও এটাই ব্যবহার করে। দলিল রেজিস্ট্রিতে দুই পক্ষেরই NID বা পাসপোর্ট লাগে, আর অনলাইন রেজিস্ট্রির পাইলটও NID-এর সাথে যুক্ত।
- **"NID না থাকলে?"** জন্ম নিবন্ধন নম্বর বা পাসপোর্ট দিয়ে করা যাবে। এটা পরের ধাপে আসবে।
- **"নোটিশের ৭২ ঘণ্টা কি রেজিস্ট্রি ধীর করবে না?"** ৩ দিন খুব কম সময়। এর বিনিময়ে বছরের পর বছর মামলা এড়ানো যায়। আর মালিক নিজে ডিজিটাল সম্মতি দিলে সময় কমানোর নিয়মও রাখা যায়।
- **"এসক্রো কে চালাবে?"** তফসিলি ব্যাংক। এটা আইনগত ও নীতিগত সিদ্ধান্তের বিষয়, তাই ডেমোতে আমরা প্রবাহটা দেখিয়েছি।
- **"বিদ্যমান সিস্টেম ভাঙবে?"** না। ই-নামজারি, ই-পর্চা আর ভূমি উন্নয়ন কর যেমন আছে তেমনই থাকবে। ভূমিসূত্র API দিয়ে তাদের পাশে একটা যাচাই স্তর হিসেবে কাজ করবে।
